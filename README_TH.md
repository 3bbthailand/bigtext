# BigText: เปิดไฟล์ TXT ขนาดใหญ่บน Windows

ดับเบิลคลิก `Open_BigText.cmd` ในโฟลเดอร์โปรเจกต์ แล้วกด **เปิดไฟล์…**

โปรแกรมใช้ Python 3.11 ขึ้นไปและ Tkinter ซึ่งมีอยู่ในเครื่องนี้แล้ว ไม่ต้องติดตั้งไลบรารีเพิ่มเติม ไม่ส่งข้อมูลไฟล์ขึ้นอินเทอร์เน็ต และเปิดต้นฉบับแบบอ่านอย่างเดียว

## ภาษาเมนู (English / ไทย / 日本語)

เมนูเริ่มต้นเป็นภาษาอังกฤษ กดปุ่ม **English**, **ไทย** หรือ **日本語** ที่มุมขวาบน (แถบสีน้ำเงินเข้ม) เพื่อเปลี่ยนได้ทันทีโดยไม่ต้องเปิดโปรแกรมใหม่ โปรแกรมจำภาษาที่เลือกไว้ใน `%APPDATA%\BigText\settings.json` ข้อความเมนูอยู่ใน `large_text\i18n.py` ส่วนคำสั่งบรรทัดคำสั่ง (`bigtext.py`) ยังเป็นภาษาอังกฤษ

## โหมดมืด / สว่าง

เปิดมาเป็นโหมดมืดก่อน กดปุ่ม **☾ Dark** หรือ **☀ Light** ที่มุมขวาบน (ทางซ้ายของปุ่มภาษา) เพื่อสลับได้ทันที โปรแกรมจำไว้ในไฟล์ settings เดียวกับภาษา แถบชื่อหน้าต่างจะมืดตามด้วย (Windows 10 20H1 ขึ้นไป) ส่วนหน้าต่างเปิดไฟล์/บันทึกไฟล์และกล่องข้อความแจ้งเตือนเป็นของ Windows จึงยังเป็นสีตามระบบ สีทั้งหมดอยู่ใน `large_text\theme.py` และมีเทสต์ตรวจว่าตัวหนังสือทุกจุดมีความต่างสีกับพื้นหลังอย่างน้อย 7:1 (ปุ่มสีน้ำเงิน 4.5:1)

เมนูภาษาญี่ปุ่นใช้ฟอนต์ Meiryo UI ส่วนชื่อไฟล์ ช่องค้นหา แถบสถานะ และเนื้อหาไฟล์ใช้ Tahoma ทุกภาษา เพราะ Meiryo UI แสดงตัวไทยเล็กมาก

## วิธีที่แนะนำ: อ่านทีละหน้าเสมือน

ไม่จำเป็นต้องแบ่งไฟล์จริงก่อนอ่าน โปรแกรมใช้ตำแหน่ง byte เพื่ออ่านเฉพาะหน้าที่ต้องการ ขนาดเริ่มต้น 1 MiB จึงไม่ต้องอ่านทั้งไฟล์เพื่อสร้างดัชนีบรรทัดก่อนเปิด

- **ก่อนหน้า / ถัดไป**: เลื่อนทีละส่วน แสดงเลขหน้า เช่น 1 / 102,400
- **ไปหน้า**: พิมพ์เลขหน้าเพื่อข้ามไปทันที
- **ไป %**: ไปยังช่วง 0–100% ของไฟล์
- **MiB/หน้า**: เลือก 0.0625, 0.25, 1 หรือ 4 MiB
- **ค้นหาถัดไป**: ค้นหาแบบข้อความตรงตัว แยกตัวพิมพ์ใหญ่/เล็ก เริ่มจากหน้าปัจจุบันหรือผลค้นหาล่าสุด
- **บันทึกหน้านี้เป็น UTF-8**: สร้างไฟล์เล็กเฉพาะช่วงที่กำลังดู พร้อม BOM เพื่อให้โปรแกรม Windows ตรวจ encoding ได้
- **หยุดงาน**: หยุดค้นหาหรือแบ่งไฟล์ โดยไม่ต้องรอจนครบทั้งไฟล์

ปุ่มลัด: `Ctrl+O` เปิดไฟล์, `Ctrl+F` ช่องค้นหา, `Ctrl+←/→` เลื่อนหน้า, `Ctrl+A` เลือกข้อความในหน้าปัจจุบัน

เลขหน้าอ้างอิงขนาด byte ไม่ใช่เลขบรรทัด ขอบเขตหน้าอาจเลื่อนเล็กน้อยเพื่อไม่ตัดกลางอักษร Unicode หลังค้นหา หน้าต่างจะแสดงบริบทใกล้ข้อความที่พบ

การเลื่อนสกรอลล์เป็นการเลื่อนภายในหน้าปัจจุบัน หากไฟล์มีบรรทัดยาวมาก ให้ปิดการตัดบรรทัดตามหน้าต่างและลด MiB/หน้าเพื่อให้หน้าต่างตอบสนองเร็วขึ้น

## Encoding และภาษาไทย

`auto` ตรวจ BOM ของ UTF-8, UTF-16 และ UTF-32 หากไม่มี BOM จะเริ่มด้วย UTF-8 ไม่ได้เดา encoding ทุกชนิด

- ไฟล์ภาษาไทยรุ่นเก่า: เลือก `cp874` หรือ Windows-874
- UTF-16 ที่ไม่มี BOM: เลือก `utf-16-le` หรือ `utf-16-be` ให้ตรงกับต้นฉบับ
- ไฟล์ตะวันตกแบบเก่า: เลือก `cp1252` หรือ `latin-1`

หากถอดรหัสไม่ได้ โปรแกรมจะแสดงคำเตือนและอักขระแทนในหน้าต่าง การแบ่งไฟล์ยังคัดลอก bytes เดิมโดยไม่แก้ไข ส่วนการส่งออกหน้าเป็น UTF-8 ใช้ข้อความตาม encoding ที่เลือก จึงควรเลือกให้ถูกก่อนส่งออก

## แบ่งเป็นไฟล์ย่อย

1. เปิดต้นฉบับ แล้วเลือกแท็บ **แบ่งเป็นไฟล์ย่อย**
2. ระบุขนาด เช่น 1, 10 หรือ 100 MiB และโฟลเดอร์ปลายทาง
3. กด **เริ่มแบ่งไฟล์** โปรแกรมสร้างโฟลเดอร์ใหม่ให้ทุกครั้ง

ขนาดเป็นเพดานสูงสุด ไม่รวม metadata ในโฟลเดอร์ ถ้าต้องการรักษาบรรทัด โปรแกรมจะหาจบบรรทัดในช่วง 64 KiB ก่อนเพดาน ถ้าไม่พบ จะตัดบรรทัดยาวโดยรักษาขอบเขตอักษร เพื่อไม่ให้ไฟล์ย่อยใหญ่เกินกำหนด

ไฟล์ UTF-16/32 จะได้รับ BOM เพิ่มเมื่อจำเป็น เพื่อให้เปิดแต่ละส่วนได้อย่างอิสระ ข้อมูล BOM ที่เพิ่มจะบันทึกใน manifest เพื่อให้รวมกลับเป็น bytes ต้นฉบับได้ตรงกัน

ตัวอย่างผลลัพธ์:

```text
source_parts_วันที่_เวลา_รหัส/
  manifest.json
  parts.jsonl
  group_00001/
    part_00000001.txt
    part_00000002.txt
  group_00002/
    part_00001001.txt
```

แต่ละกลุ่มมีไม่เกิน 1,000 ไฟล์ เพื่อให้ Explorer จัดการได้สะดวกขึ้น ไฟล์ต้นฉบับและไฟล์ปลายทางที่มีอยู่แล้วจะไม่ถูกเขียนทับ

ไฟล์ 100 GB แบบฐานสิบ แบ่งที่ 1 MiB จะมีประมาณ 95,368 ส่วนขึ้นไป ส่วนไฟล์ 100 GiB จะมี 102,400 ส่วนขึ้นไป การแบ่งจริงต้องใช้พื้นที่สำเนาเพิ่มใกล้เคียงขนาดต้นฉบับ จึงเหมาะกับกรณีที่ต้องส่งออกหลายส่วนจริง ๆ

ถ้าหยุดหรือเกิดข้อผิดพลาด ไฟล์ที่เสร็จแล้วจะอยู่ต่อ และ manifest ระบุสถานะ `cancelled` หรือ `error` ไฟล์ส่วนที่ยังเขียนไม่เสร็จจะถูกลบเมื่อหยุดตามปกติ ถ้าเครื่องดับหรือโปรเซสถูกบังคับปิด อาจเหลือ `.partial` ได้ โปรแกรมไม่รวมชุดที่ยังไม่ครบกลับ และยังไม่มีระบบ resume การแบ่ง ให้เริ่มงานใหม่ในโฟลเดอร์ใหม่

## คำสั่งสำหรับงานอัตโนมัติ

เปิด PowerShell ในโฟลเดอร์โปรเจกต์:

```powershell
py -3.11 bigtext.py info "H:\data\huge.txt"
py -3.11 bigtext.py page "H:\data\huge.txt" --number 100 --size-mib 1 --out "H:\data\page100.txt"
py -3.11 bigtext.py search "H:\data\huge.txt" "ข้อความที่ต้องการ"
py -3.11 bigtext.py split "H:\data\huge.txt" --size-mib 1 --out "H:\data\new_parts"
py -3.11 bigtext.py join "H:\data\new_parts" --out "H:\data\restored.txt"
```

เพิ่ม `--encoding cp874` ได้ในคำสั่ง info/page/search/split ส่วน `--exact-size` ใน split ปิดการเลือกจบบรรทัด แต่ขอบเขตยังปรับเพื่อรักษา Unicode ทำให้บางส่วนเล็กกว่าค่าที่ตั้งไว้เล็กน้อย

คำสั่ง join ตรวจ SHA-256 ของทุกส่วนและลบเฉพาะ BOM ที่โปรแกรมเพิ่ม ก่อนสร้างต้นฉบับกลับ โปรแกรมจะไม่เขียนทับชื่อไฟล์ที่มีอยู่แล้ว

## การออกแบบและข้อจำกัด

ค้นคว้าโครงการ [klogg](https://github.com/variar/klogg) และ [glogg](https://github.com/nickbnf/glogg) ซึ่งใช้แนวทางอ่านไฟล์จากดิสก์โดยไม่โหลดทั้งไฟล์เข้า RAM ก่อนเลือกสร้างเครื่องมือ Python ขนาดเล็กนี้ขึ้นใหม่ให้ตรงกับการแบ่งหน้า/ส่งออกไฟล์บนเครื่องนี้ ไม่ได้คัดลอกหรือ fork ซอร์สโค้ดจากสองโครงการนั้น

- Viewer อ่านไม่เกินขนาดหน้าบวกไม่กี่ bytes; split/join/search ใช้บัฟเฟอร์ประมาณ 1 MiB ต่อรอบ ไม่มีรายการทุกบรรทัดใน RAM
- การค้นหาที่ไม่พบต้องอ่านตั้งแต่จุดเริ่มค้นหาจนถึงท้ายไฟล์ ระยะเวลาจึงขึ้นกับความเร็วดิสก์และขนาดข้อมูล
- ไม่แก้ไขไฟล์ต้นฉบับ ไม่ค้นหา regex ไม่แสดงเลขบรรทัดทั้งไฟล์ และไม่อ่านไฟล์บีบอัดโดยตรง
- ถ้าไฟล์ถูกแก้ไขระหว่างงาน โปรแกรมหยุดเมื่อพบว่าขนาดหรือเวลาแก้ไขเปลี่ยน แล้วให้เปิดไฟล์ใหม่ การตรวจนี้ไม่ใช่การล็อกไฟล์หรือป้องกันการดัดแปลง timestamp
- รูปแบบ UTF ที่ไม่ถูกต้องตั้งแต่ต้นอาจแสดงอักขระแทน การแบ่งและรวมกลับยังรักษา bytes เดิม
- ใช้ Python 64-bit สำหรับไฟล์ใหญ่มาก
- Tk บน Windows วาดข้อความทีละประมาณ 200 bytes ถ้ารอยต่อตกหน้าสระหรือวรรณยุกต์ไทย จะเห็นวงกลมประ เช่น "ใช◌้" โปรแกรมแก้โดยแบ่งบรรทัดยาวเป็นช่วงที่เริ่มด้วยพยัญชนะเสมอ แต่ทำเฉพาะ 1,000 ช่วงแรกของแต่ละบรรทัด (ประมาณ 60,000 ตัวอักษรไทย) เพื่อไม่ให้หน้าโหลดช้า บรรทัดที่ยาวกว่านั้นอาจเห็นวงกลมประในส่วนท้าย ให้ลด MiB/หน้า

## ทดสอบ

```powershell
py -3.11 -m unittest discover -s tests -v
py -3.11 verify_large_files.py --logical-gib 100 --real-mib 64
```

การทดสอบขนาดใหญ่สร้างไฟล์ sparse 100 GiB เพื่อทดสอบการอ่านต้น/กลาง/ท้ายและค้นหาใกล้ท้ายไฟล์ โดยใช้พื้นที่จริงเพียงเล็กน้อย และทดสอบอ่านค้นหาครบไฟล์ แบ่ง และรวมกลับบนไฟล์จริง 64 MiB แยกกัน ไม่ใช่ผลวัดความเร็วอ่านหรือแบ่งไฟล์จริง 100 GiB ทั้งไฟล์

บน Windows สคริปต์จะเปิดใช้งาน sparse ก่อนตั้งขนาดไฟล์ หากระบบไฟล์ไม่รองรับจะหยุด ไม่สร้างไฟล์เต็ม 100 GiB แทน ไฟล์ทดสอบชั่วคราวจะถูกลบหลังจบ ผลตรวจบันทึกใน `reports/large_file_verification.json` ตัวเลข memory เป็น peak ของ Python allocations ระหว่างตรวจ ไม่ใช่ RAM ทั้งระบบหรือ RAM ของหน้าต่าง GUI
